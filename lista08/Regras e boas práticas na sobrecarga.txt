(a) Criar um operador novo, inexistente na linguagem — Não permitido: A linguagem C++ possui um conjunto fixo e fechado de tokens reconhecidos como operadores pela sua gramática léxica e sintática. Não é possível inventar símbolos inéditos (como ** para exponenciação ou @ para operações customizadas), sendo permitida apenas a sobrecarga de operadores preexistentes na tabela oficial da linguagem (com exceção de operadores restritos como ::, ., .* e ?:).

(b) Alterar a precedência de + — Não permitido: A precedência, a associatividade e a aridade (quantidade de operandos) dos operadores são fixadas estaticamente na gramática do compilador C++ e não podem ser modificadas pelo programador. Mesmo quando o operador + é sobrecarregado para tipos definidos pelo usuário, ele continuará possuindo exatamente a mesma prioridade de avaliação e associatividade da esquerda para a direita que possui para tipos primitivos.

(c) Sobrecarregar a soma entre objetos de uma classe própria — Permitido: A sobrecarga de operadores em C++ foi projetada especificamente para estender a sintaxe dos operadores nativos a tipos definidos pelo usuário (class, struct ou enum). Desde que pelo menos um dos operandos seja de um tipo definido pelo usuário, o compilador permite definir uma função operator+ (como método membro ou função livre) para especificar o comportamento da operação entre objetos daquela classe.

(d) Redefinir a soma entre dois valores int — Não permitido: A especificação do C++ proíbe estritamente a sobrecarga de operadores cujos parâmetros sejam exclusivamente tipos primitivos embutidos (built-in types), como int, double ou ponteiros. Essa restrição impede que o programador altere a semântica fundamental e a previsibilidade das operações aritméticas básicas da linguagem, exigindo sempre pelo menos um operando do tipo classe ou enumeração na assinatura do operador sobrecarregado.

(e) Utilizar + para excluir registros — Sintaticamente permitido, mas semanticamente incorreto: Embora o compilador permita implementar qualquer lógica arbitrária dentro de um operator+ envolvendo uma classe própria, utilizar o símbolo de adição para remover dados viola diretamente o princípio da menor surpresa (Principle of Least Astonishment), o qual estabelece que um componente deve comportar-se de maneira coerente com as expectativas intuitivas estabelecidas pela convenção matemática e pela própria linguagem. Uma sobrecarga contra-intuitiva compromete severamente a legibilidade do código, induz outros desenvolvedores a erros lógicos graves durante a manutenção (como provocar perda acidental de dados ao interpretar uma expressão lista + registro como inserção) e invalida o propósito da sobrecarga, que é aumentar a clareza expressiva; para operações destrutivas sem equivalente aritmético óbvio, deve-se optar por métodos nomeados explicitamente, como excluirRegistro().
